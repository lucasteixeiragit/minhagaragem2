================================================================================
                            ROTAS IMPLEMENTADAS
================================================================================

1. POST /api/vinculos
   - Criar vínculo (PENDENTE)
   - Fluxo: Mecânica convida ou Cliente solicita
   - Validações: tipo, usuarioId, mecanicaId, duplicação
   - Auditoria: CREATE_VINCULO

2. GET /api/vinculos
   - Listar vínculos do usuário autenticado
   - USER: suas mecânicas
   - MECANICA: seus clientes
   - ADMIN: todos

3. GET /api/vinculos/meus-clientes
   - Listar clientes ATIVOS da mecânica
   - Restrição: MECANICA
   - Retorna: dados do cliente (nome, email)

4. GET /api/vinculos/minhas-mecanicas
   - Listar mecânicas ATIVAS do cliente
   - Restrição: USER
   - Retorna: dados da mecânica (nome, email)

5. POST /api/vinculos/:id/aceitar
   - Aceitar vínculo (PENDENTE → ATIVO)
   - Restrição: USER (cliente)
   - Validações: propriedade, status
   - Auditoria: ACCEPT_VINCULO

6. POST /api/vinculos/:id/recusar
   - Recusar vínculo (PENDENTE → RECUSADO)
   - Restrição: USER (cliente)
   - Validações: propriedade, status
   - Auditoria: REJECT_VINCULO

7. PATCH /api/vinculos/:id/desativar
   - Desativar vínculo (ATIVO → INATIVO)
   - Restrição: USER ou MECANICA
   - Validações: propriedade, status
   - Auditoria: DEACTIVATE_VINCULO

8. PATCH /api/vinculos/:id/bloquear
   - Bloquear vínculo (qualquer → BLOQUEADO)
   - Restrição: ADMIN
   - Validações: status
   - Auditoria: BLOCK_VINCULO

9. PATCH /api/vinculos/:id/desbloquear
   - Desbloquear vínculo (BLOQUEADO → ATIVO)
   - Restrição: ADMIN
   - Validações: status
   - Auditoria: UNBLOCK_VINCULO

================================================================================
                            ESTADOS DO VÍNCULO
================================================================================

PENDENTE   - Convite/solicitação não aceito (Sem acesso)
ATIVO      - Relacionamento válido (Com acesso)
RECUSADO   - Uma das partes recusou (Sem acesso)
INATIVO    - Vínculo encerrado (Sem acesso)
BLOQUEADO  - Bloqueado por admin (Sem acesso)

================================================================================
                            FLUXOS DE NEGÓCIO
================================================================================

Fluxo 1: Mecânica Convida Cliente
1. Mecânica envia POST /api/vinculos { usuarioId, tipo: "CONVITE" }
2. Vínculo criado em status PENDENTE
3. Cliente recebe notificação
4. Cliente envia POST /api/vinculos/:id/aceitar
5. Vínculo muda para ATIVO
6. Mecânica pode acessar veículos do cliente

Fluxo 2: Cliente Solicita Mecânica
1. Cliente envia POST /api/vinculos { mecanicaId, tipo: "SOLICITACAO" }
2. Vínculo criado em status PENDENTE
3. Mecânica recebe notificação
4. Cliente envia POST /api/vinculos/:id/aceitar
5. Vínculo muda para ATIVO
6. Mecânica pode acessar veículos do cliente

Fluxo 3: Desativação de Vínculo
1. Vínculo em status ATIVO
2. USER ou MECANICA envia PATCH /api/vinculos/:id/desativar
3. Vínculo muda para INATIVO
4. Histórico preservado (não apagado)
5. Mecânica não pode mais acessar veículos

Fluxo 4: Bloqueio Administrativo
1. ADMIN envia PATCH /api/vinculos/:id/bloquear
2. Vínculo muda para BLOQUEADO
3. Acesso completamente negado
4. ADMIN pode desbloquear com PATCH /api/vinculos/:id/desbloquear

   queries frequentes.
